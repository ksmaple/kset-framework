同步调用 / 结果条件分支以标签说明异常与恢复

范围与角色

本图说明当前 kset-agent-core 的一次同步 run/resume 调用及其条件分支。宿主调用方负责发起任务、装配模型/工具/检查点、读取快照、权限和权威结果核验；Kernel 负责轮次、状态转换、停止与结构化返回。图中“宿主项目”是 SPI 边界，不代表仓库内已有特定宿主实现。未涵盖 Spring/Web 入口、数据库表、SSE、RAG 业务、生产运行状态或跨会话调度。

时序行按一次运行的主线排列；红色行表示在相邻主线位置发生的条件分支，不表示每次运行都执行。图中“代码可见”只说明源码存在，不表示生产已启用或验收已完成。本次变更类型与交付完成状态均为“不适用”。

交互与依据

N01 新任务入口

调用
宿主 → AgentLoopKernel.run，进程内同步调用
数据
task、protocolId、agentRunId 或生成器
结果
校验协议并建立初始 AgentRunState

代码可见：缺少 agentRunId 时生成，生成失败在进入循环前抛出稳定错误。一个 agentRunId 标识一次可恢复任务，不等于 sessionId、计划 taskId 或 invocationId。依据：AgentLoopKernel.run / bindAgentRunId，对象契约。

N02 初始检查点

调用
Kernel → AgentCheckpointPort.save
数据
不可变 AgentRunSnapshot v4、请求上下文
结果
调用开始的运行状态交给宿主端口

代码可见：RUN_STARTED 监听后先保存快照，再进入循环。端口默认可为 noop，Core 不读取快照，不指定数据库或表。宿主存储实现和条件写是否配置待核实。依据：execute / saveCheckpoint，AgentCheckpointPort。

N03 轮次前停止判断

调用
Kernel → AgentStopController.evaluate
数据
当前状态、限制、调用 deadline 和取消信号
结果
继续或生成停止决定

代码可见：每轮前检查线程中断、用户取消、超时、已完成/暂停/失败、最大轮次、协议错误数、无进展数，再检查宿主策略。默认限制见 AgentLoopOptions。无互斥锁；同一 Kernel 的调用局部状态彼此独立，宿主负责会话单飞。依据：AgentStopController，AgentLoopOptions。

N04 ReAct 生成本轮请求

调用
Kernel → AgentReasoningStrategy.nextTurn
数据
任务、工具目录、Observation、有限状态投影
结果
AgentTurn / ModelRequest

代码可见：默认 ReAct 根据计划、工具观察和回答分片判定 planning/acting/evaluating/answering；只把白名单状态与批准 ID 放入模型上下文，宿主业务属性不自动透传。自定义策略可替换。依据：ReactReasoningStrategy，AgentKernelBuilder。

N05 协议准备

调用
Kernel → AgentProtocolCodec.prepare
数据
ModelRequest、protocolId
结果
补充协议说明的模型请求

代码可见：内置 agent-json:v1 在 system prompt 追加控制格式说明；注册其他 Codec 后，新请求仍须显式选择协议。运行中及恢复不能更换协议。依据：AgentJsonV1Codec.prepare，prepareModelRequest。

N06 模型调用

调用
Kernel → 宿主 AgentModel.generate，同步 SPI
数据
ModelRequest、AgentExecutionContext
结果
ModelResponse 或结构化失败

代码可见：仅 retryable 的 MODEL_CALL_FAILED 在默认最多 3 次内指数退避重试；等待计入 invocationTimeout，取消/中断/超时阻止下一次调用。外部模型传输协议和实际服务端点不在 Core，待宿主核实。依据：generateModelWithRetry，AgentModel。

N07 模型响应

调用
AgentModel → Kernel，同步返回
数据
响应文本、可选原生工具调用与指标
结果
进入协议解码

代码可见：响应由宿主适配为 ModelResponse，Kernel 发送模型完成生命周期事件后才解码；核心不负责 HTTP、供应商 SDK 或 SSE。依据：ModelResponse，execute。

N08 解码与校验

调用
Kernel → Codec.decode，随后 Strategy.validate
数据
ModelResponse、待处理动作和 callId
结果
AgentDecision 与标准/扩展动作

代码可见：内置 JSON 使用成对标记和严格字段；无标记普通文本成为 final_answer。动作包括计划、单工具、批次、分片、最终回答、确认。Kernel 检查重复/冲突 callId、待处理动作重述、决策容量，策略检查阶段允许的动作及计划任务引用。依据：AgentJsonV1Codec.decode，execute / validateToolCallIds。

N09 可纠正协议错误

调用
Codec/Strategy → Kernel，条件分支
数据
AgentProtocolException、错误码
结果
记录协议失败，未超限则保存快照并进入下一轮

代码可见：连续协议错误达到限制或达到其他停止条件时转为 FAILED；错误未超限时保存失败信息并继续。非协议运行时异常进入 fail，并尝试保存 FAILED 快照。依据：execute 的 AgentProtocolException 分支，evaluate。

N10 工具执行前检查点

调用
Kernel → CheckpointPort.save，条件为可暂存的标准工具动作
数据
完整调用身份、pending action、reconciliationPending
结果
先保存 RUNNING 快照，再分发工具动作

代码可见：ToolCallAction/ToolBatchAction 在 canStageToolAction 允许时，先调用 beforeToolDispatch，再保存快照；已批准且缺少原待处理证据的动作不靠新记录证明批准。崩溃后该快照只表示可能执行，不能据此认定工具结果。依据：execute / canStageToolAction，AgentRunState.beforeToolDispatch。

N11 动作分发

调用
Kernel → AgentActionRegistry → Handler
数据
AgentAction、当前状态、ExecutionContext
结果
AgentActionResult

代码可见：构建器注册标准 Handler（计划、工具、批次、回答分片、最终回答、确认），扩展动作需注册对应 Handler。默认工具注册表在 build 时冻结；默认 Executor 为同步执行。依据：AgentKernelBuilder.build，StandardActionHandlers.create。

N12 等待批准

调用
Handler → Kernel，条件为确认动作或未批准的危险工具
数据
confirmationId 或 callId，pending action/批次
结果
SUSPENDED；stopMessage 提示等待输入

代码可见：非只读工具或标记 requiresConfirmation 的工具需要批准；确认动作也会暂停。批次保存原调用顺序并逐项批准。新 run 预置批准 ID 不可绕过待处理动作；批准只是确认，不是权限凭据。依据：ToolCallHandler / ToolBatchHandler / ConfirmationHandler，pendingApprovalResult。

N13 工具执行

调用
Handler → 宿主 AgentTool.execute，同步 SPI；批次经宿主 Executor 提交
数据
arguments、callId、taskId、(agentRunId, callId)、deadline
结果
结构化 ToolExecutionResult 或异常

代码可见：单工具按调用及活动 deadline 检查；批次并发任务等待 toolBatchTimeout，超时后取消 Future 不保证已启动副作用停止。Core 不持有互斥锁，宿主工具适配器负责权限和持久幂等；(agentRunId, callId) 是结构化幂等键。依据：ToolCallHandler / ToolBatchHandler，AgentToolContext。

N14 工具结果转观察

调用
AgentTool → Handler，同步返回
数据
ToolExecutionResult、callId、taskId、toolName
结果
AgentObservation 进入后续模型上下文

代码可见：结果经 toObservation 转为 Observation；只读工具的异常或 null 可成为明确失败，有副作用工具的异常或 null 被保守地判为未知结果。工具结果不是 Kernel 停止决定。依据：toObservation / uncertainToolFailure，AgentObservation。

N15 未知结果暂停核验

调用
Handler → Kernel，条件为 TOOL_RESULT_UNKNOWN
数据
pending action、完整批次、未知结果观察
结果
RECONCILIATION_REQUIRED + SUSPENDED

代码可见：单工具未知结果或批次部分未知/超时，进入暂停核验；不继续后续动作。宿主须从权威来源判定原调用结果，不能凭快照或 Future 取消推断副作用。依据：suspendForReconciliation，reconciliationStop。

N16 更新运行状态

调用
Handler → Kernel
数据
observations、状态属性、可选 answer/suspensionMessage
结果
不可变 AgentRunState.apply

代码可见：普通动作结果反馈到下一轮；final_answer 合并已积累回答分片并请求 COMPLETED；确认、工具或扩展动作可请求暂停。模型原始思维链不写快照。依据：AnswerChunkHandler / FinalAnswerHandler，AgentRunState.apply。

N17 动作后与终态检查点

调用
Kernel → CheckpointPort.save
数据
动作后状态或 stopDecision 的 v4 快照
结果
保存成功后才推进下一动作或返回

代码可见：非终态动作后保存并判断是否继续；finish 保存停止快照再通知监听器并返回。接口只定义写入，物理库表、revision 与 fencing 由宿主实现。依据：execute / finish / saveCheckpoint，AgentCheckpointPort。

N18 检查点失败

调用
CheckpointPort → Kernel，条件为保存异常
数据
CHECKPOINT_FAILED，原异常保留
结果
活动运行返回 FAILED；快照不可视为已持久化

代码可见：保存失败发出 CHECKPOINT_FAILED 事件并中止后续动作；失败态再次保存也失败时返回的 AgentFailure 优先报告 CHECKPOINT_FAILED。默认 noop 端口仅用于不要求持久化的接入。依据：saveCheckpoint / saveFailureCheckpoint / fail。

N19 集中停止判断

调用
Kernel → AgentStopController
数据
状态、动作结果、停止策略
结果
COMPLETED / SUSPENDED / FAILED / CANCELLED 或继续

代码可见：动作间还检查取消、超时、无进展与宿主策略；停止策略不得凭空将任务设为 COMPLETED。未知工具结果专门映射 RECONCILIATION_REQUIRED。停止优先级和最终状态由 Controller 与 Kernel 共同固定。依据：AgentStopController，execute / reconciliationStop。

N20 返回调用结果

调用
Kernel → 宿主，进程内同步返回
数据
agentRunId、runStatus、stopDecision、snapshot、failure
结果
COMPLETED 时有 answer；SUSPENDED 时 answer 为 null

代码可见：生命周期 Listener 接收停止和返回事件；Listener 是只读观测，不是恢复权威数据源。状态与失败码供宿主展示或后续处理，Core 不直接提供 Web/SSE 响应。依据：result / notifyResult，AgentResult。

N21 批准或拒绝后恢复

调用
宿主 → Kernel.resume，条件为等待批准
数据
原 agentRunId、task、protocolId、v4 快照、批准/拒绝 ID
结果
拒绝生成 Observation；批准后要求首动作完整重述

代码可见：缺少对应批准 ID、批准与拒绝冲突、待处理动作不匹配均显式失败；拒绝工具不会执行该工具。宿主负责读取快照和真实权限核验。依据：resume，pendingApprovalResult / validatePendingDecision。

N22 权威结果核验后恢复

调用
宿主 → Kernel.resume(request, snapshot, input)
数据
每个 pending callId 的权威 AgentObservation
结果
核对身份并应用结果后进入新模型轮次

代码可见：RUNNING 执行前快照及 RECONCILIATION_REQUIRED 暂停快照需要完整权威 Observation；callId/taskId/toolName、覆盖数量和非 UNKNOWN 结果均校验。Core 不查询外部系统或自动补偿。依据：apply / validateObservation，resume。

N23 恢复输入拒绝

调用
Kernel → 宿主，条件为前置校验失败
数据
快照版本/身份、协议、任务、待处理结果
结果
抛出 INVALID_SNAPSHOT / INVALID_RESUME_INPUT 等错误，不进入新轮次

代码可见：COMPLETED/CANCELLED 不能恢复；请求与快照身份、协议、任务须一致。未知结果未提供权威 Observation 时，在 execute 前拒绝。进入 execute 后的运行时故障则转为 FAILED AgentResult。依据：resume / execute / fail，apply。

项目适配与边界

涉及的 Core 包：api（请求/结果）、loop（状态和循环）、strategy（默认 ReAct）、protocol（版本化解码）、model（模型 SPI）、action（动作）、tool（工具 SPI）、stop（停止）、checkpoint（只写快照）、event（只读观测）、id（ID 生成）。对象与字段以 core-object-contract.md 为准。Core 不读写数据库表；实际数据库、表名及网络调用由宿主适配决定，不能从接口推断。

并发边界：Kernel 的单次执行状态、deadline、invocationId 和事件序号是调用局部的；共享 Model、Codec、Strategy、Handler、Tool、CheckpointPort、Listener、Executor 需由宿主保证线程安全。工具操作依靠稳定 callId 与宿主幂等机制，Core 不提供跨进程互斥锁或 exactly-once。默认同步 Executor 不创建线程；批次并行取决于宿主提供的 Executor。

数据流：N01 的任务输入进入 N04/N05 模型请求；N07 的响应经 N08 变成动作；N13/N14 的工具结果经 N16 成为下一轮 Observation；N17 交给宿主保存快照；N20 只在 COMPLETED 返回最终 answer。没有 Core 内部权威数据库落点。异常主线分别见 N09、N12、N15、N18、N21–N23。
