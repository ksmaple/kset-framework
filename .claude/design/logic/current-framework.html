E22 Agent 入口

调用
宿主 → AgentLoopKernel.run/resume，同步 Java API

resume 校验 run ID、协议与任务一致，完成或取消的快照不可恢复。依据：AgentLoopKernel。

E23 Agent 扩展调用

调用
Agent 内核 → 宿主 Model / Tool / Checkpoint SPI
数据
模型请求、动作与工具调用、运行快照
结果

内核驱动停止条件与时序；模型、工具和持久化由宿主注入，不能把快照返回等同于持久化成功。依据：AgentLoopKernel、对象契约。

E24 Agent 结果

调用
Agent 内核 → 宿主
数据
AgentResult、AgentRunSnapshot、可选 AgentFailure
结果
COMPLETED / SUSPENDED / FAILED / CANCELLED

最终答案仅完成态有效；技术故障与业务动作失败分层表示。依据：AgentResult、对象契约。

对象与数据落点

公开对象和配置字段的逐字段定义见 当前代码对象与字段定义。Agent 的身份、状态和快照语义另见 Agent Core 对象契约。本仓不定义使用方业务表；图中可核实的持久化表为 schedule 的 t_kset_schedule_lock。Redis session 和缓存是组件存储，业务权威数据由使用方决定。

适用边界与待核实项

各阶段表示独立触发的可组合路径，纵向顺序只在阶段内表示调用顺序；不能推断一个应用同时启用了全部 starter。业务 HTTP 路径、Dubbo 服务、MQ topic 与业务表由使用方配置，本仓无法核实。源码可见不表示生产已运行或已验收。本次为现状说明，变更类型与交付状态不适用；未提出优化评估，建议项不适用。
