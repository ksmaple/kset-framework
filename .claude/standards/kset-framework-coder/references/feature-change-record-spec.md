# 功能变更记录规范

FCR001: 同一功能再次调优或替换实现时须创建或更新 `.claude/design/changes/{feature-key}.md`
FCR002: feature-key 须使用稳定的 kebab-case 业务功能名，与同一功能的现状说明和需求设计共用文件键；按项目规则 R140 核对所属项目和现有文件归属，禁止按日期或实现技术反复更名及覆盖其他功能记录
FCR003: 功能变更记录须在修改源码前读取，并在变更计划中列出当前实现、被替代实现与本轮影响范围
FCR004: 功能变更记录只保存项目内相对文件路径、类或方法等符号、入口关系和状态，禁止复制源码正文
FCR005: 功能变更记录禁止收录编译产物、生成源码、运行日志、凭据、令牌或敏感配置值
FCR006: 每轮调优须分配稳定 change-id，并记录日期、目标、上线状态判定、兼容选择、替代目标、基线 Git ref、结果 Git ref 与回滚来源；未知值写 N/A
FCR007: 每轮调优须按文件记录相对路径、相关符号、职责、动作与状态，动作限定为 add、modify、retain、deprecate、remove
FCR008: 新记录的实现状态取值限定为 active、active-compatible、removed；待退役但仍可供旧调用方使用的实现标为 active-compatible，不为回滚保留无生产用途的源码；历史记录中的 rollback-candidate、removable 保留原时点事实，不再用于新记录或回写历史
FCR009: 同一功能同时只能有一个 active 实现，仍承接旧调用方的兼容实现须标为 active-compatible
FCR010: 新实现接管入口后，未承接生产流量且已移除的旧实现须标为 removed，并关联可恢复该实现的 Git ref；仍留在源码中的旧实现须记录实际状态与清理条件
FCR011: 回滚来源须记录可定位的基线 Git ref；无法定位时写 N/A 并标记回滚不可用
FCR012: 删除旧实现前须确认无生产调用、兼容迁移完成，并在变更计划中列出受影响入口与回滚影响
FCR013: 删除文件、方法、接口、路由或配置后须将对应项标为 removed，并保留删除 change-id 与已知 Git ref
FCR014: 回滚须由用户选择目标 change-id，再按记录指定的 Git ref 恢复入口关系、配置与必要文件，禁止仅凭最近一次修改猜测回滚范围
FCR015: 回滚完成后须将目标实现标为 active，并按实际处理结果记录被撤销实现的状态
FCR016: 缺少历史记录时只允许根据当前源码建立基线，禁止虚构旧 change-id、调用关系或 Git ref；目标实现无可定位 Git ref 时须标记回滚不可用
FCR017: 每轮兼容变更须记录上线状态判定时间、判定结果、判定证据与证据来源；证据不足或冲突时须记录待确认及用户确认结论
FCR018: 每轮兼容变更须记录判定时点的基线 Git ref、当前入口、接口契约、已知调用方、迁移状态与实现状态，禁止只写开发未上线或已上线结论
FCR019: 上线状态是对应 change-id 判定时点的历史事实，后续上线、回滚或再次迭代须新增记录，禁止回写旧 change-id 的状态与代码快照
FCR020: 自动判定为已上线须关联可定位功能版本的生产发布、部署或使用证据；仅有源码、分支、标签外观或未关联生产环境的构建记录时不得判定已上线
FCR021: 功能变更记录中的新旧版本对比须单独保存本次任务首次确定的正式线上主分支名称、已发布提交的完整 Git SHA 及发布或部署证据；仅在主分支开发的项目还须记录目标环境实际使用的正式发布版本及其与提交的对应关系，未发布的 HEAD 不得充当旧版。同一任务后续 change-id 沿用该 SHA，轮次基线与结果 Git ref 仅用于追踪迭代和回滚，不得替代旧版本基线。无法确认分支或已发布提交，或单主分支项目无法确认正式发布版本时写待确认，不得虚构旧版差异

## 记录结构

```markdown
# {功能名称} 变更记录

- feature-key：`{feature-key}`
- 当前 change-id：`{change-id}`
- 当前状态：`active`
- 当前入口：`相对路径#类或方法`

## 实现索引

| change-id | 状态 | 入口 | 替代目标 | 回滚来源 | 回滚可用性 | 清理条件 |
| --- | --- | --- | --- | --- | --- | --- |

## {change-id}

- 日期：YYYY-MM-DD
- 目标：本轮功能调整目标
- 判定时间：YYYY-MM-DD HH:mm:ss + 时区
- 上线状态：开发未上线 / 已上线 / 待确认 / 不涉及兼容
- 判定方式：自动判定 / 用户确认 / N/A
- 判定证据：发布或部署记录 / 版本标签与发布映射 / 生产调用 / 调用方迁移 / 功能变更记录 / N/A
- 证据来源：项目内相对路径、Git ref 或外部记录名称；未知写 N/A
- 当时代码状态：入口、接口契约、已知调用方、迁移状态与实现状态摘要
- 兼容选择：兼容增量 / 版本并行 / 直接替换 / N/A
- 回滚目标：`{change-id}` 或 N/A
- 旧版本正式线上主分支及对比基线 Git SHA：本次任务首次确定的分支名、已发布提交的完整 SHA 与发布或部署证据；无法确认写待确认
- 旧版正式发布版本（仅主分支开发项目）：目标环境实际使用的版本标识及其与基线 SHA 的对应证据；不适用写 N/A，无法确认写待确认
- 基线 Git ref：修改前可定位提交；未知写 N/A
- 结果 Git ref：本轮提交后补充；未提交或未知写 N/A
- 回滚来源：Git ref / N/A
- 回滚可用性：可用 / 不可用

| 文件 | 符号 | 职责 | 动作 | 状态 |
| --- | --- | --- | --- | --- |

### 回滚步骤

1. 恢复目标 change-id 对应入口关系。
2. 恢复目标配置、路由或适配器。
3. 更新本记录中的实现状态。
```
