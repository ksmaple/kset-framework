# 日志规则

R141: 新增业务日志前须核对 project-spec、现有日志框架、切面、拦截器、异常处理与慢日志采集；沿用项目格式和字段名，避免同一事件重复记录或为单个功能另建日志体系
R142: 请求、任务与消息处理的关键结果和失败须能以 traceId 或稳定执行标识关联；跨线程与远程调用须传播或关联原 traceId，处理结束须清理线程日志上下文
R143: 日志等级按诊断目的选择：正常阶段结果用 INFO，需处理的异常用 ERROR，循环或批量中的逐条细节用 DEBUG；预期业务拒绝仅在需要排查时记录，禁止在每次请求均执行的路径中无条件打印需完整序列化的对象
R144: 未预期系统异常须在负责处理的边界记录业务标识、失败阶段及完整异常栈，避免沿调用链重复记录；日志不得代替业务事实、审计记录或幂等状态
R145: 日志禁止记录密码、令牌、密钥、Cookie、完整请求/响应体、原始 SQL 绑定参数及其他敏感原值；必要的个人信息和参数摘要须按项目约定脱敏
R146: 慢日志须优先沿用项目阈值与采集规则；无现成规则且本次确需新增时，按接口、SQL、外部调用或消息消费的实际延迟与流量确定阈值，静态自查等级、关联字段、脱敏、异常栈及高频输出成本
R147: 新增或修改的业务方法仅在包含多条业务分支、状态或数值变化、跨服务编排、批量重试或补偿等复杂逻辑，且现有日志不足以还原处理路径时记录方法级结果日志；简单委托、直接查询和纯映射方法不记录方法级日志，修改时清理其无诊断价值的存量打印
R148: 复杂方法需要结果日志时，须包含稳定的方法或操作名、业务标识、分支标识、结果状态及解释分支判定、状态变化或失败原因所需的字段；禁止为凑字段打印全部入参、返回对象或敏感原值
R149: 复杂方法原有分支日志的有效判断依据和关键字段须保留或等价并入结果日志；复杂分支可追加日志，但须沿用同一 traceId、业务标识和字段名，避免无意义的进入/退出日志
R150: 复杂方法异常退出且处理边界无法还原失败分支时，才在方法内补充一次必要上下文；不得为满足方法日志要求逐层捕获或重复打印堆栈，堆栈按 R144 在处理边界记录，循环或批量调用的方法按 R143 选择 DEBUG 并遵守 R145 脱敏边界
R151: 循环或批量处理中各项执行相同业务逻辑时，禁止逐项打印相同的成功日志；须在批次边界一次记录总数、成功数、失败数、业务标识与必要的失败摘要
R152: 各项命中不同分支或结果且确需展示差异时，须提取脱敏后的必要字段组成列表并在批次边界一次打印，禁止仅为日志逐行遍历打印；列表超出项目日志单行容量或条数上限时只记录总数、分类数量与有限样本或异常项
R153: 复杂方法的结果日志不得导致循环内逐项输出 INFO；被循环调用且确需日志的方法可按 R143 使用 DEBUG，批次边界仍须按 R151–R152 记录汇总与差异信息
R154: 业务方法结果、关键分支与失败日志须显式记录该事件定位所需且已安全取得的核心及关联业务 ID，如订单号、任务 ID、事件 ID、操作者 UID 和目标用户 UID；尚未取得的 ID 不得为日志额外查询，批量 ID 按 R156 限量记录
R155: 同一日志涉及多个用户 UID 或其他同类型 ID 时，须按业务角色使用稳定且不同的字段名，如 operatorUid、targetUid、inviterUid；沿用项目已有命名约定，禁止 uid1、uid2 或不同角色共用一个 uid 字段
R156: 批量关联 ID 按 R151–R152 记录有限列表、分类样本或可追溯的批次 ID，禁止逐条或无界打印；项目认定为敏感的 ID 须掩码或映射，姓名、联系方式及认证凭据仍按 R145 处理
R157: 未预期系统异常不得被吞掉；非处理边界须抛出原异常或保留 cause 向上传播。承担失败隔离或补偿的处理边界须记录原异常，按业务影响、权威事实及契约选择停止、继续、核验或恢复；不影响主结果的附属异常可按既有口径记录后继续。持久化失败或重试状态仅作为可靠恢复场景的默认参考，只有契约明确要求或现有事实不足以恢复核心结果时才使用，不是所有业务的必选项；禁止将影响主结果的失败仅打印后继续、返回成功或用默认值掩盖
R158: 系统异常由最终处理边界记录异常类型、消息、完整堆栈、traceId、核心业务 ID 与必要上下文；对外响应遵循项目错误契约，不得直接暴露内部堆栈或敏感异常消息
R159: 预期内业务自定义异常按业务错误码与响应契约抛出或转换，不强制打印 ERROR 或完整堆栈；确需记录日志时保留业务标识和失败分支，禁止将未预期系统异常伪装成业务异常后吞掉
R160: 业务日志 message 优先在同一条日志中按稳定字段名打印必要的 field=value，并使用项目日志框架的参数化占位符；尽量不把完整请求、响应或领域对象序列化为 JSON 打印，已确认的诊断例外仍须遵守 R145 脱敏边界
R161: 打印 object.field 或多级字段前须对可能为 null 的每一级对象引用判空，先安全提取字段再记录；日志取值不得引发 NullPointerException 或改变业务结果，缺失值不得伪装成 0、false 或空字符串
R162: 列表日志须提取标量字段组成有界快照后一次输出，禁止把业务对象列表交给日志框架隐式格式化、序列化完整对象列表或逐项打印多行；项目采集端已有 JSON 编码时仍沿用其配置
R163: 日志调用参数只使用已取得的稳定标量、空值安全的局部字段、按 R162 准备的有界标量快照及需记录堆栈的异常对象；禁止在参数中调用业务方法、链式 getter、toString、JSON 序列化、流处理或其他可能抛错或有副作用的逻辑，参数化占位符不豁免求值风险
R164: 日志字段须来自业务流程已取得的数据或安全提取的局部值；仅为日志不得执行远程调用、数据库查询或改变状态的计算，字段无法安全取得时记录明确空值或省略，日志准备不得覆盖原业务异常或改变业务结果
R165: 复杂流程现有日志不足以定位早期失败时，在首个关键风险操作前记录一次当时可安全取得的 traceId、适用业务 ID、操作和阶段；前置日志只表明开始或尝试，成功日志待结果确认后记录，异常处理边界补充已取得的定位字段、失败阶段和原异常堆栈
R166: 静态自查须检查每个日志点的参数求值、隐式对象格式化、空值、脱敏及前置、成功、异常日志顺序；禁止日志构造失败遮蔽原异常、提前打印成功或逐步重复打印相同上下文
