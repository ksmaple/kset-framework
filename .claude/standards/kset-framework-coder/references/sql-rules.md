# 数据库与 SQL 规则

R085: 数据库变更前须根据 project-spec、项目文档、构建配置、迁移目录与同类 SQL 识别项目已有数据库变更规范及版本化迁移框架
R085a: 项目已有明确数据库变更规范时须优先遵循该规范，R087–R100 仅补充项目未约定的事项
R086: 项目已接入版本化迁移框架时须遵循现有框架目录、命名、版本和迁移机制，R087–R100 不适用
R087: 项目无明确数据库变更规范且未接入版本化迁移框架时，每次数据库功能变更的 SQL 产出固定为一个初始化 SQL 文件和一个本次新增的独立增量 SQL 文件
R088: 初始化 SQL 文件名须以稳定的功能名称作为主体
R089: 增量 SQL 文件名须复用初始化 SQL 的功能名称主体，并仅追加项目既有的统一增量标识后缀；项目尚无既有后缀时，须先与用户确认后缀再使用
R090: 初始化 SQL 须表达全新部署时应得到的最新完整结构与当前有效数据
R091: 增量 SQL 须表达从上一已发布数据库版本升级到当前版本所需的全部操作
R092: 表、字段、索引或约束变更须同步修改初始化 SQL 中的 CREATE TABLE 或初始化 DDL
R093: 表、字段、索引或约束变更须在本次增量 SQL 中写入对应的 CREATE、ALTER 或 DROP DDL
R094: 初始化数据发生替换或删除时须从初始化 SQL 移除旧版本数据语句并仅保留当前有效数据
R095: 初始化数据发生替换或删除时须在本次增量 SQL 中先清理或更新旧版本数据，再写入当前版本新增数据
R096: 修正已发布数据库状态时只能新增本次功能增量 SQL，历史增量 SQL 文件视为不可变基线
R097: 同一功能涉及多个表、字段、索引、约束或数据操作时须合并在本次唯一的增量 SQL 文件中，并按依赖顺序组织语句
R098: 静态自查须分别核对全新初始化结果与历史版本执行增量后的结果在目标结构和有效数据上等价
R099: 初始化 SQL 与增量 SQL 的文件头须使用同一个中文功能名称说明变更用途
R100: 初始化 SQL 与增量 SQL 的目录须按 project-spec、项目现有 SQL 根目录及同类脚本布局确定，禁止硬编码固定目录
R100a: 编写或修改 CREATE TABLE、ALTER TABLE 时不得写表级 DEFAULT CHARSET、CHARACTER SET 或 COLLATE，须继承数据库默认值；仅当 project-spec 明确记录项目例外时按其约定执行
R100b: 修改当前有效的初始化或建表 SQL 时须检查并迁移已有表级字符设置；确认目标数据库默认字符集和排序规则与原预期一致后删除显式声明，不一致时先明确数据库默认配置或在 project-spec 记录例外；禁止为此回写已发布增量 SQL
R100c: 正式 SQL、迁移和数据脚本须按项目规则 R142 保留在项目既有可执行目录并正常版本管理；用户要求另存 SQL 设计材料时，结构、迁移和数据草案分别按项目规则 R142 归入 `.claude/design/sql/schema/`、`sql/migration/`、`sql/data/`，不得以草案替代正式脚本
R105: 新增索引前须明确其服务的稳定业务唯一性约束或实际 WHERE、JOIN、ORDER BY、GROUP BY 访问路径，禁止仅因字段或参数存在而建索引
R106: 稳定业务唯一键须优先建立唯一约束或唯一索引
R107: 多租户数据的业务唯一键须把租户隔离维度纳入唯一键
R108: 存量表新增唯一约束前须检查并处置重复数据
R109: 唯一约束须明确逻辑删除记录是否继续占用业务键，并使用目标数据库版本实际支持的方案
R110: 用户、类型、状态和时间等真实查询维度可按访问路径建立组合索引
R111: 类型、状态、deleted 等低基数字段禁止脱离高选择性维度机械建立单列索引
R112: 时间列用于范围过滤、时间排序或游标时须放在相关等值过滤列之后；时间等值过滤按 R115 的等值列顺序设计，并以实际查询路径和执行计划验证
R112a: 仅明确的全局时间窗口、归档清理或时间排序查询允许单独建立时间索引
R113: 金额、余额、金币、积分、库存、额度、价格、数量、变更值、差值与增减量等值类字段禁止作为普通索引列
R114: 仅用于写入、展示、计算、请求透传或局部变量映射且不参与查询条件、唯一约束或锁定条件的字段禁止建索引
R115: 组合索引须按稳定等值与高选择性维度、类型或状态、范围或排序时间的顺序设计
R116: 新增索引前须排除被主键、唯一索引或现有组合索引左前缀覆盖的冗余索引
R116a: 索引数量须保持完成约束与核心查询所需的最小集合
R117: 索引变更须使用目标数据库版本支持的执行计划结合数据量、基数与写入成本验证
R117a: 普通索引禁止替代本应由唯一约束保证的并发正确性
R118: 纯查询入口禁止使用 `@Transactional`、`TransactionTemplate` 或手动事务，包括只读事务；普通写入先核对单条原子条件写或唯一约束能否保证正确性。新增或扩大显式本地写事务须按项目规则 R078 说明必要性并取得用户对事务方案的明确授权；获授权后只覆盖保证同一数据库业务不变量所必需的读写操作
R119: 事务须在第一个需要一致性保护的数据库操作前开启，并在最后一个相关写入完成后立即提交或回滚
R120: 参数校验、数据转换、纯计算、跨记录规则编排、HTTP、RPC、MQ、文件 IO、等待与大结果组装须放在事务外执行
R121: 写事务内查询只允许读取后续条件写入或本地不变量校验所必需的数据，禁止在事务内全量扫描后循环处理业务；有界批次的必要读写按 R123 使用独立短事务
R122: 单条原子条件 UPDATE、INSERT、upsert 或唯一约束已能保证正确性时，禁止扩大为多语句事务
R123: 批量处理须拆分为有界批次；单记录或批次确需多语句原子提交且按项目规则 R078 获授权时使用独立短事务，禁止在全量扫描和批次间保持同一事务
R124: 禁止通过外层大方法的 `@Transactional` 或等价编程式事务无意扩大事务范围，确需事务时须由项目实际事务机制下的最小内部方法承担；Java/Spring 项目须确认代理入口生效
R124a: 移出事务的预处理不得替代提交前必需的并发校验；拆分时须保留本地状态与幂等结果的原子提交，禁止产生先查后写竞态或部分提交
R125: Java SQL 字符串、MyBatis XML、注解 SQL、ORM 自定义 SQL 及其他代码内 SQL 须只写表名，禁止添加数据库名或逻辑库名前缀
R126: 独立可执行且用于发布、升级或初始化的纯 `.sql` 脚本中，所有表引用须写成 project-spec 约定的逻辑库名.表名
R129: 业务表只承载所属业务模型的字段，其他模型专属字段须另建所属模型的关联表
R130: 跨业务模型字段共表须经用户明确允许，并在 project-spec 记录归属、理由、写入责任及拆分影响
R131: 跨模块关联须使用稳定语义业务标识，禁止依赖对方数据库物理主键
R132: 一对一扩展表须对关联键建立唯一约束
R133: 一对多关联表须明确行级业务标识，存在业务唯一性或幂等要求时须建立相应唯一约束
R134: 外部业务快照仅保留本业务必需的语义字段，并记录采集时点或来源
R294: 新增或修改字段时按项目规则 R168 核对值域、类型、精度、长度、非空与默认值、注释及存量回填；长整型定点小数字段核对整数列与缩放单位、小数位一致；大文本、二进制或 JSON 字段按真实大小与访问频率评估拆分和关联约束，不为推测容量机械拆表
R295: 新增或修改查询时按项目规则 R169 显式投影必要列，列表、分页、批量、关联及导出不使用 `SELECT *`，大字段仅在必要详情路径有界读取；核对隔离条件、稳定排序、结果上限、深分页方式、参数绑定与动态排序允许列表
R296: 涉及索引访问路径时按项目规则 R170 核对列和参数类型、排序规则、组合索引前缀及函数、转换、前置通配和跨列 `OR` 的实际影响；以目标版本执行计划结合数据量与参数分布检查扫描、回表、排序、临时结果和写入成本，不以索引存在代替验证
R297: 写事务内查询按项目规则 R171 只取本地不变量所需的列和有界行，核对索引、隔离级别、锁定范围与加锁顺序；读取后写入仍须条件写、唯一约束或必要锁定读取守住并发条件，异常按框架规则回滚，不吞异常后误提交
R298: 处理死锁、锁等待超时或提交结果未知时按项目规则 R172 核对数据库错误与死锁证据、完整回滚、幂等重做条件及有界退避；发现相反锁顺序、扫描扩大锁范围或长事务时先修复，禁止对业务冲突和外部副作用盲目重试
