# kset-framework-environment

> 执行约束以 [项目规则](../../rules/kset-framework-project-rules.md) 为准；项目事实见 [project-spec.md](../kset-framework-coder/references/project-spec.md) 的「环境连接与日志索引」及「部署入口与回滚索引」。本规范不得覆盖或放宽项目规则。

## 触发条件

**启用**：当前任务命中规范 `kset-framework-environment` 的适用范围时读取；适用于环境连接、运行数据和日志、已指定环境的修改或部署，具体操作仍按项目规则授权。

**不启用**：业务源码与配置修改、代码缺陷修复和测试属于其他角色。

## 核心规则

R000: 本规范仅在 kset-framework（proj=kset-framework）所属项目仓库及其工作树使用，跨项目任务须使用目标项目自己的规则与规范
R001: 先读项目规则和 project-spec 的环境索引，再依据当前运行配置或部署事实确认项目、环境、组件、实例与连接来源。
R002: 环境索引缺项时仅从项目内相对配置路径、已确认的部署文档和现有连接工具定位；无法确认映射或访问权限时列出缺项，禁止凭名称猜测连接目标。
R003: 环境索引只记录非敏感定位信息、密钥引用和核验状态；禁止保存密码、令牌、私钥、完整带凭据 URI、原始连接输出或日志正文。
R004: 凭据仅经目标项目已有的授权密钥来源或现有客户端使用，不在命令参数、对话、终端输出、进程列表、文档和临时文件中展开原值。
R005: 查询前限定数据库表或业务键、Redis 完整 Key、服务器实例、日志时间窗与最大结果量；使用项目现有只读连接和客户端能力。
R006: 数据库查询使用参数化条件与有界结果；Redis 按已知完整 Key 查询，禁止 `KEYS`、Key 空间 `SCAN`、`MATCH`、通配符与前缀模糊查询及其封装入口；未知 Key 时报告缺少定位依据，不遍历 Key 空间。
R007: 日志按明确的服务、实例和时间窗收集；输出按项目日志规则脱敏，只返回诊断所需的有限片段与来源位置。
R008: 修改前确认用户授权的目标环境、具体对象和预期结果，记录当前状态、影响范围、执行步骤与恢复办法；无法预览影响或恢复时停止修改并说明。
R009: 仅在已授权范围执行数据库、Redis 或服务器变更；执行后按同一目标回查结果，记录执行时间、脱敏证据和未完成项。
R010: 修改业务源码仍由 `kset-framework-coder` 或 `kset-framework-fixer` 负责；环境数据修改授权不扩展为编译、测试、部署或无关实例操作，部署须另按项目规则 R043–R044、R129–R131 执行。
R011: 多步骤环境任务遵循项目规则的任务清单与完成门禁；未核实连接目标、结果或恢复条件时不得报告完成。
R012: 部署前从 project-spec 与当前部署事实确认目标环境、服务及实例、当前版本、待发布版本与产物来源、部署入口、配置差异、健康检查及回滚入口；任一关键映射冲突时停止。
R013: 仅在用户当前对话明确要求部署并指定目标环境后，按项目现有发布流程执行必要步骤；不能把数据修改、编译或测试授权当作部署授权，也不自动扩大到其他环境或服务。
R014: 每个发布步骤核对真实结果；部署后核验版本、健康状态和相关日志，失败或结果未知时停止后续发布，回滚仅在已授权部署计划覆盖或另获明确授权时执行。
R015: 部署计划与环境核验结果默认在对话中交付；用户要求保存文件时按项目规则 R141 分别写入 `.claude/design/plans/deployment/` 与 `.claude/design/reports/environment/`，只记录非敏感目标、步骤和已核实结果；计划文件不构成部署授权
R016: 按项目规则 R142 区分项目既有可执行部署清单、构建或制品库中的发布包，以及按需保存的非敏感协作文件：清单说明归 `.claude/design/deploy/manifests/`、实际发布记录归 `deploy/releases/`、回滚说明归 `deploy/rollbacks/`；发布记录须有实际核验结果和产物标识，不能从计划推定已部署，也不得复制制品本体或凭据
R017: Redis Cluster 查询须按项目规则 R160–R164 核对目标节点、DB 0、槽归属与只读命令边界；普通排查不得执行高影响命令，专门维护仅在当前对话明确授权环境、节点或槽、命令范围与维护窗口且已有运维流程可核对影响、恢复及结果时执行

## 工作流

```text
Step 1: 读取项目规则与环境索引，按目标服务和环境定位配置来源、连接别名与密钥引用
Step 2: 核对实际连接目标、权限、只读或修改范围；缺项时报告并补充经确认的非敏感项目事实
Step 3: 有查询或日志请求时，按 references/environment-operations.md 的组件方法执行有界读取
Step 4: 有数据库、Redis 或服务器配置修改授权时先展示目标、差异、影响和恢复办法，再执行并回查
Step 4a: 有部署请求时按项目规则核对授权和部署索引，列出发布、核验、回滚步骤后按范围执行
Step 5: 输出环境、目标、来源、实际结果、脱敏证据和未覆盖项
```
