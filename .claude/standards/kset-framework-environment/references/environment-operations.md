# 环境连接、数据与部署操作方法

> 本文只给出选择方法，不存放可直接连接的凭据。目标项目的实际路径、别名和密钥引用以 project-spec 的「环境连接与日志索引」及当前配置为准。

R001: 每次先确定 `kset-framework`、环境、服务、实例、组件和操作对象，并以配置来源或已确认的连接别名核对目标；同名服务跨环境不得仅凭名称选择。
R002: 读取顺序为 project-spec 索引、项目运行配置和部署清单、项目文档、现有连接工具；发现过期或冲突信息时以可定位的当前部署事实核实并更新索引。
R003: 连接信息分为非敏感定位字段和凭据引用；凭据由现有密钥管理器、环境注入或客户端配置在执行时读取，不复制原值到命令行、文档或输出。
R004: 无现成客户端、权限或目标映射时报告缺项，不安装新工具、不跨环境借用凭据、不尝试默认密码。

| 目标 | 优先定位位置 | 核对重点 |
|------|--------------|----------|
| 数据库 | `application*.yml` / `application*.properties`、项目配置模块、部署清单或配置中心引用 | 环境 profile、逻辑库、读写角色、实例映射 |
| Redis | 项目缓存配置、部署清单或配置中心引用 | 实例、逻辑 DB、服务与租户 Key 前缀 |
| 服务器 | 项目部署文档、编排清单及已授权的 SSH 客户端配置 | 环境、服务、主机或容器实例标识 |
| 日志 | 项目日志配置、日志平台索引或服务部署信息 | 服务名、实例、时区、保留期限与检索字段 |

这些位置只是检索候选，不能据文件名推定实际部署目标；配置中心或密钥管理器不可访问时记录引用与缺项。

## 数据库

R005: 先核对数据库类型、逻辑库、读写角色和目标实例；只读查询使用参数化条件、明确列与行数上限，优先按主键或索引过滤。
R006: 执行修改前展示参数化语句或迁移步骤、命中条件、预计影响行数、事务或备份方案；执行后查询权威库核对结果，结果未知时先核验再决定是否重试。

常用路径：查看表结构与索引；按业务键查询有限记录；统计受影响行数；在获授权后执行条件更新或项目已有迁移机制。命令和 SQL 方言以项目现有客户端及 project-spec 的兼容基线为准。

## Redis

R007: 先核对实例、完整 Key、类型和 TTL；Cluster 另按项目规则 R160–R161 核对 DB 0、目标节点与槽归属，不以单节点统计代表全局。大 Key 排查先用项目现有监控及针对确切 Key 的 `MEMORY USAGE`、`STRLEN`、`HLEN`、`SCARD`、`ZCARD` 或 `LLEN` 等适用指标，不全量读取值。禁止 `KEYS`、Key 空间 `SCAN`、`MATCH`、通配符或前缀模糊查询及其封装入口，未知 Key 时报告缺少定位依据，不遍历 Key 空间。禁止 `FLUSHDB`、`FLUSHALL` 等实例级清空操作。
R008: 修改前记录目标完整 Key 的类型、TTL 和当前值摘要，核对是否可恢复；按项目现有客户端或适配能力选择原子命令，禁止 Redis 服务端脚本，并按项目规则 R162–R164 排除高影响管理命令与无界操作。专门集群维护须另核对项目规则 R163 的授权和运维流程；执行后复查目标节点、类型、值和 TTL。

常用路径：从业务标识构造完整 Key，查看 `TYPE`、`TTL` 与有限值；获授权后修改指定 Key、过期时间或删除已确认的 Key。共享实例还须核对租户与服务命名空间。

## 服务器与日志

R009: 优先使用项目已登记的 SSH 别名、容器平台或日志平台入口；连接后核对主机或实例标识，再读取进程与日志状态。
R010: 日志查询限定服务、实例、时间窗和行数，按 traceId 或稳定业务 ID 关联；只保存脱敏片段、时间、来源与检索条件，不落盘原始全量日志。
R011: 服务器配置、文件、服务状态或部署操作须分别核对项目规则的授权边界；修改前保留可恢复版本与目标差异，修改后核对服务状态和目标文件。

常用路径：查看服务状态、磁盘与端口占用；按时间和关键词查询日志；按 traceId 汇总跨实例片段；获授权后修改明确的配置对象并核验。日志平台与 SSH 的优先级以项目实际部署方式为准。

## 部署

R012: 从项目现有发布文档、CI/CD 定义、编排清单和 project-spec 部署索引确认部署入口；不能仅凭仓库中存在脚本或镜像名推断实际生产发布流程。
R013: 部署计划须列明目标环境、服务与实例、当前版本、待发布 Git ref 与产物、配置和数据库迁移依赖、执行顺序、健康检查、观察窗口、回滚入口及回滚触发条件。
R014: 用户明确要求部署且指定目标环境后，仅使用已确认的项目发布流程执行必要构建、打包、上传、发布与服务启停；运行测试、本地开发服务器和其他环境仍按项目规则独立约束。
R015: 按项目现有批次或实例顺序发布并核对每步结果；失败、版本不符或结果未知时停止后续步骤，只有已授权计划涵盖回滚或另获明确授权时才执行回滚。
R016: 发布后核对实际版本、健康检查、关键日志及适用业务入口；记录时间、目标、版本、发布入口、脱敏证据、未覆盖项和回滚状态，不把命令成功等同于部署成功。
R016a: 需落盘的部署记录按项目规则 R142 只保存非敏感版本、来源、校验和与实际核验结果；发布包仍由项目既有构建输出或制品库管理，可执行部署清单仍在项目既有目录，计划和草案均不得冒充实际发布记录。

常用入口：项目既有 CI/CD 流水线、容器编排发布、服务器部署脚本或手工发布流程。先按索引和当前部署事实选择实际使用的入口；没有可确认的入口、产物或回滚路径时报告缺项，不拼装新的部署命令。

## 结果格式

R017: 输出项目、环境、服务与实例、连接定位依据、操作对象、时间窗或查询上限、实际结果、脱敏证据和未覆盖项；不展示凭据或未请求的大量业务数据。
