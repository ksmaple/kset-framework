# kset-framework 产品 PRD 规范

> project-init 生成。本文件是项目作用域的产品文档规范，不是独立规范。执行约束以 [项目规则](../rules/kset-framework-project-rules.md) 为准，项目事实以 [project-spec](../../docs/overview/design/project-spec.md) 为准；文档状态与证据按 [项目文档规范](../standards/kset-framework-requirements-designer/references/project-documentation.md) 处理。

## 适用范围

依据产品目标、原始需求、业务方确认或原型编写、整理及评审 PRD 时使用。需要核对源码现状和实现位置的需求设计仍由项目需求设计角色处理；不得把产品设想写成已实现事实。

## 规范

R001: 开始前确定完整 PRD 或独立交互说明、需求来源、目标用户、涉及端、本期范围及已有正式文档位置。
R002: 业务规则、术语、状态、数值和配置须有可定位来源；证据不足标为待决，影响主流程成立的缺口标为阻塞。
R003: 完整 PRD 须覆盖目标、范围、触发与可观察结果、主流程、适用异常与恢复、功能步骤、输入输出及可判定的验收条件；先绘制分端着色、带 P 编号和图例的整体业务流程图，概览节点只写稳定业务环节。
R003a: 完整 PRD 的功能详述须按客户端、运营端、服务端分段，各段按 P 编号排列；不涉及的端须在涉及端声明中说明。客户端与运营端先给页面流转或原型说明，服务端先给逻辑流程图。
R004: 多端参与同一业务步骤时，分别说明入口、动作、责任、可见结果和数据来源；有页面的流程说明默认、加载、空、错误及极限状态。
R005: 展示字段说明来源、业务含义、格式和空值表现；运营配置说明权限、留痕、数据口径与变更责任，未确认的参考值不得写成定值。
R006: 迭代型 PRD 列明新增、修改与删除内容，保持术语、流程、原型、字段、验收项及埋点说明的一致性。
R007: 交付前逐条件核对原始需求与正文，列出范围外事项、冲突和待决项；原型可见事实与推断规则须分开。
R008: PRD 的评审通过、代码实现、测试通过和正式发布分别记录证据；缺少证据时保持未验证或待核实，不因文档已写成推断功能完成。

## 文档输出

沿用项目已有正式 PRD 与用户指定路径；本地协作草稿按项目规则分类。只有实际需要文件时才落盘，不为每个功能预建 PRD。产品侧说明与同一功能需求设计通过稳定编号互相定位。
