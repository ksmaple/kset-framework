# kset-framework 需求讨论

> project-init 生成。

> 仅适用于当前项目；[项目规则](../../rules/kset-framework-project-rules.md) 与 [project-spec](../kset-framework-coder/references/project-spec.md) 分别是执行约束和项目事实来源。

## 触发条件

**启用**：当前任务命中规范 `kset-framework-requirements-discussion`，用户希望通过多轮讨论形成领域模型和详细功能列表。

**不启用**：仅整理完整 PRD 使用项目 PRD 规范；核对源码和实现映射使用 `kset-framework-requirements-designer`；业务实现使用 `kset-framework-coder`。

## 核心规则

R000: 本规范仅适用于（proj=kset-framework）所属项目仓库及其工作树；不得引用平台 `kaka-*` 规则或规范，不覆盖项目规则或已有契约。
R001: 先核对目标用户、业务目标、现有材料、项目事实与本期范围；分清已确认事实、假设和待决问题，不将讨论草案当作需求基线。
R002: 从商业价值、用户任务、产品取舍、业务规则和 DDD 边界五个视角讨论；商业判断须有受益方、可观察结果及依据，不虚构访谈和收益数字。
R003: 围绕会改变业务边界、关键规则或本期范围的问题成组提问；收到回答后回写事实状态、待决项、模型和功能列表，并说明范围变化。
R004: 产品范围区分本期、后续和不做；本期须形成可验证的最小业务闭环，功能优先级须说明用户价值、商业收益或风险、成本及依赖，依据不足时标为待验证。
R005: 领域模型先定义统一语言与限界上下文，再逐上下文说明聚合、实体、值对象、行为、不变量、状态、领域事件和跨上下文关系；不按页面或数据表机械划分聚合。
R006: 详细功能列表按场景或业务能力分组，每项赋稳定 ID，包含角色、触发、前置条件、主流程、异常、结果、业务规则、验收条件、范围、优先级依据及模型关联。
R007: 双向核对场景、价值、业务规则、领域模型和功能项；未确认的关键决策保持草案状态，不声称需求已冻结。
R008: 多轮补充反复暴露同类可复用规则缺口时，先更新本次产物，再对照本项目已有规范提炼候选规则；项目事实不得写成通则。
R009: 讨论结果需要源码依据或实现设计时移交 `kset-framework-requirements-designer` 或 `kset-framework-coder`；本规范不修改业务源码。
R010: 经核对属于项目通用规则且在当前授权范围内时，按项目规则及 `kset-framework-skill-rule-helper`（若已生成）修订本规范；跨项目通用候选交平台规范维护入口审查，不在本项目复制平台正文。
R011: 讨论按输入澄清、价值与范围、用户流程、适用的事件风暴、领域模型和功能清单推进；用户流程指从触发需求、执行操作到成功或失败恢复的连续步骤；未确认前提只阻塞依赖它的结论，关键阶段须记录待决问题。
R012: 建模前须将关键用户任务关联成功口径、业务指标、交互状态与失败恢复；复杂价值切片须梳理命令、业务事件、政策、异常及补偿后再确定领域边界，具体界面与技术设计交对应项目规范。
R013: 检查相关的运营、客服、数据、安全、合规、财务及外部伙伴视角，逐项标记已覆盖、不适用或待补充；关键规则须记录来源、适用范围、例外、责任角色及验收关联。
R014: 需要业务、产品、体验、架构或其他专业决策时列明待确认角色，不虚构评审或批准；场景、规则、事件、功能和验收须能互相追溯，未确认的责任与风险判断保持待决。
R015: 以表格交付核心业务流程时，至少列出流程标题、流程、规则、异常和改进点；每行的异常须说明该流程适用的失败、冲突、超时、重复、拒绝或补偿，未知项标为【待决】，不适用项说明依据，并关联规则或验收标识。

## 工作流

```text
Step 1: 确认目标、来源、项目事实与待决问题
Step 2: 先讨论价值、范围与指标，再梳理用户流程、关键状态和失败恢复；收到补充时回到受影响的问题
Step 3: 对复杂切片开展事件风暴，形成按上下文划分的领域模型和按能力分组的功能列表
Step 4: 核对业务视角、优先级依据及价值、场景、规则、模型、功能和验收的追踪关系，交付待决项
Step 5: 回顾多轮反馈，将通用规则缺口按项目规范维护流程处理
```

## 交付结构

| 部分 | 最低内容 |
|------|----------|
| 讨论结论 | 目标、受益方、成功口径、本期边界、取舍和依据状态 |
| 用户流程与业务视角 | 关键状态、失败恢复、指标关联；相关视角的覆盖、不适用或待补充状态 |
| 核心业务流程表（使用表格时） | 流程标题、流程、规则、异常、改进点；逐行说明异常及规则或验收关联 |
| 事件与规则 | 适用切片的命令、事件、政策、异常及补偿；规则来源、责任、例外和验收关联 |
| 领域模型 | 统一语言、上下文地图、各上下文的聚合与行为、不变量、状态、事件及跨上下文关系 |
| 功能列表 | 稳定 ID、场景与价值、上下文或聚合、角色、触发、前置、主流程、异常、结果、规则、验收、范围、优先级依据与依赖 |
| 待决与反馈 | 决策问题、选项及影响、推荐方案；每轮补充对产物的影响和通用规则候选 |
