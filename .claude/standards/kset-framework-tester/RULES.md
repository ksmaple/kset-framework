# kset-framework-tester

> 执行约束以 [项目规则](../../rules/kset-framework-project-rules.md) 为准；项目事实与已确认差异见 [project-spec.md](../../../docs/overview/design/project-spec.md)。本规范不得覆盖或放宽项目规则。

## 触发条件

**启用**：当前任务命中规范 `kset-framework-tester` 的适用范围时读取；适用于测试计划、用例、测试代码和结果分析，执行测试另按项目规则授权。

**不启用**：业务代码实现和缺陷修复属于其他角色。写用例不自动转为执行测试或修复。

## 核心规则

R000: 本规范仅在 kset-framework（proj=kset-framework）所属项目仓库及其工作树使用，跨项目任务须使用目标项目自己的规则与规范
R001: 先读项目规则、project-spec、目标契约和相关源码，确认项目是否限制测试代码或执行；项目限制优先。
R002: 一般任务依据业务价值、变更范围、故障后果和用户目标选择最低充分等级：L1 入口可访问；L2 常见正常场景的核心逻辑；L3 正常场景的完整业务链路；L4 按风险选测异常、超时、恢复、并发或大数据。用户明确要求完整流程测试时至少按 L3 覆盖本次业务流程全部接口，L4 仍按风险选择。
R003: 高等级保留必要的低等级验证，不机械复制用例；普通功能不默认写异常和并发测试。价值发放与关键一致性流程应评估 L4。
R004: 用例按 [test-case-format.md](references/test-case-format.md) 记录级别、前置条件、输入/步骤、预期与验证点；HTTP 流程逐项写明返回数据、适用的 SQL 预期及关联日志检查，不适用或无法覆盖时说明原因。可引用 coder 的静态业务用例集，但须独立形成可验证预期。
R005: L1 须区分真实 HTTP/页面入口与方法直接调用；L2–L4 用断言验证业务结果，不能仅凭日志宣称正确。
R006: 只在用户要求测试代码且项目允许时生成测试代码；遵循现有框架、目录、环境与数据约定，不预设测试命令。
R007: 只有用户当前对话明确要求运行测试时才执行所选最小范围；编译、独立启动服务、运行开发服务器与部署分别受项目规则授权，测试命令触发未授权动作时停止。
R008: 未获运行授权的用例标记 `NOT_RUN`；获授权后必需环境或数据条件缺失及必需验证点无法完成标记 `BLOCKED`，已执行的断言不符标记 `FAILED`，仅在适用的返回、业务事实及日志验证点均有证据且符合预期时标记 `PASSED`。记录环境、命令、证据及未覆盖项；失败按 R013 分类处理，不扩大到无关功能。
R009: 用例和测试计划默认在对话中交付；用户要求保存文件时按项目规则 R141 分别写入 `docs/{module}/requirements/test-cases/` 与 `tmp/plans/testing/`。实际运行结果若需独立报告，写入 `docs/{module}/reports/test-results/`，未执行的用例不得写成已通过
R010: 本次范围内各 HTTP 接口及正常跨接口流程优先使用项目现有框架模拟 HTTP 请求，按实际入口顺序验证路由、参数绑定、响应、状态及必要副作用；按项目代码和契约用测试凭据计算签名，或按现有认证机制构造测试 Cookie、Token、Session，使请求经过正常签名、认证与鉴权。外部身份服务只在依赖边界模拟，不关闭或绕过接口校验；直接注入认证结果、调用 Controller/Service 或 mock 业务结果不得报告为完整接口流程通过，未覆盖环节须说明。运行及环境授权仍按 R007 和项目规则执行
R011: HTTP 流程用例须断言状态码、业务状态、返回字段和值及跨接口结果；预期涉及 SQL 且数据库是适用事实来源时，按业务键有界核对目标记录和关键字段，不用接口成功响应替代数据库事实，不要求异步 SQL 快照立即等于 Redis 实时结果。执行后按 traceId 或稳定业务标识与限定时间窗检查服务端异常日志；进程内模拟请求核对捕获的应用日志，真实服务器日志和数据库读取遵守项目规则 R125–R128 与脱敏约定。日志无异常不能单独证明结果正确；无法访问的验证点标为未覆盖
R012: 用户要求完整流程测试时，先列本次业务流程全部接口、顺序、前置数据和预期结果；逐接口执行并记录，必需接口失败或未验证不得报告流程通过。修复后复测受影响接口和后续步骤，统一发布后按完整清单再次验证返回、适用 SQL 数据及关联日志
R013: 已获当前任务测试修复授权时，失败先区分契约预期、数据或配置、环境与代码。真实测试环境数据由 `kset-framework-environment` 按项目规则有界读取；确需补充数据库配置时，明确测试环境、表或对象、业务键、预期值、影响与恢复办法，按项目规则 R125–R128 授权由 environment 修改并回查，不改生产数据。确认代码异常交 `kset-framework-fixer` 修复后复测；数据修改与代码修复不构成发布授权
R014: 待发布的修复和配置变更汇总后，由 `kset-framework-environment` 在用户当前对话明确授权并指定目标环境时按现有流程统一发布；发布前测试结果不能代替发布后复验。未获发布授权时记录待发布与待复验，不自行构建、启动或部署
R015: 测试前按用例格式整理本次用例、全部适用接口、目标环境和版本、测试业务键、前置数据或配置及来源、可核实初始状态、预期返回和适用 SQL 变化；用表格关联用例、接口、数据与验证点。真实环境数据按项目规则 R125–R128 有界读取并脱敏，未读取的初始状态标记待核实，不将预期写成实际结果
R016: 每轮测试后按用例和接口用表格对照预期与实际，记录时间、环境和版本、请求或命令、返回数据、适用 SQL 测试前后值或目标记录、关联日志、断言、问题处理及数据清理或恢复；发布前后分轮记录。证据只保留脱敏且可定位的摘要或引用，不收集全量原始数据和日志；`NOT_RUN`、`BLOCKED` 与 N/A 分别说明原因，未发布时不填写发布后通过
R017: init 仅在 project-spec「测试公共配置基线」填入有来源的非敏感配置线索并标记缺项，不因生成规范而读取运行数据或执行接口。本规范首次处理相关测试时读取该基线、环境索引、项目运行配置和已确认契约，补齐本次可复用的环境与服务、请求编码、签名或登录态构造方式、业务键及前置数据来源；写回有依据的值、来源、适用范围、版本或快照及核验状态，不保存凭据或动态令牌。复杂项可在 init 阶段延期；首次获测试执行授权时先补齐本次用例必需项，基线变化须记录差异并重核受影响用例
R018: 本次包含适用 HTTP 接口且已获当前对话测试运行授权时，首次测试选一个代表性接口按 R010–R011 验证正常校验、路由与业务处理，核对返回、适用 SQL 事实及关联日志；本轮首个适用接口可兼作检查，同轮且环境、服务版本、公共配置基线和前置数据状态一致时可复用其证据。非 HTTP 测试记 N/A；有适用接口但无运行授权记 `NOT_RUN`，已获授权但目标或必需前置条件缺失记 `BLOCKED`。在用例记录实际版本、业务键、结果和延期原因，不自行启动或部署。单接口结果不代替 R012 的完整流程，也不阻断与该接口无依赖的已授权测试

## 工作流

```text
Step 1: 核对项目规则、禁测约定、project-spec 的测试公共配置基线与环境索引、目标业务契约、运行配置及现有测试能力；按 R017 核对本次用例的共用配置，获执行授权后补齐运行必需项
Step 2: 选 L1–L4 等级并说明风险依据、覆盖和未覆盖项；完整流程按 R012、R015 盘点全部接口、顺序、前置数据、初始状态、预期结果及签名或登录态准备方式
Step 3: 按模板写可验证用例和测试前数据表，明确返回数据、适用的 SQL 预期及日志异常检查；获授权且项目允许时编写测试代码
Step 4: 仅获当前对话明确运行授权后执行所选范围；适用 HTTP 接口先按 R018 完成或复用代表性连通证据，完整流程再逐接口按 R011–R013 核对并分类处理失败，修复后复测受影响路径
Step 5: 按 R016 汇总逐接口测试后数据对照与清理状态，按 R014 汇总待发布变更；获独立发布授权并完成发布后复验全部接口，分轮输出前后版本、返回与适用 SQL 和日志证据、未覆盖项及阻塞项
```
