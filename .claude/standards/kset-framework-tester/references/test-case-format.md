# kset-framework 测试用例格式

> 本文件用于测试设计。编写用例不代表已执行，也不授权编译、独立启动或部署。项目禁测约定优先。

## 等级选择

| 等级 | 验证目标 | 典型用例 |
|------|----------|----------|
| L1 | 接口或页面入口可访问，基本请求有预期响应 | 访问入口，核对状态与基础响应 |
| L2 | 常见正常场景的核心业务逻辑正确 | 关键输入产生预期结果、状态或数据变化 |
| L3 | 正常场景的完整业务链路正确 | 多步骤状态流转、持久化与副作用一致 |
| L4 | 按实际风险选测异常、超时、恢复、并发或大数据 | 指定风险下的不变量与恢复结果 |

一般任务选择最低充分等级并说明依据；明确要求完整流程时至少按 L3 覆盖本次流程全部接口，L4 仍按风险选择。高等级保留必要的低等级检查，不复制全部用例。

## 单条用例

| 字段 | 内容 |
|------|------|
| 编号与级别 | `TC-001 / L2` |
| 场景 | 可观察的业务行为 |
| 依据 | 需求、接口契约或源码路径 |
| 前置条件 | 账号、状态、环境与数据依赖；HTTP 接口写明按真实校验逻辑准备的测试签名或登录态 |
| 输入与步骤 | 最少必要操作和数据；正常跨接口流程按实际顺序列出模拟 HTTP 请求 |
| 预期结果 | HTTP 状态码、业务状态、返回字段与值、跨接口关联结果及必要副作用 |
| SQL 预期 | 涉及 SQL 且数据库是适用事实来源时，写明业务键、目标记录、关键字段及预期变化；不适用时写 N/A |
| 日志核对 | 按 traceId 或稳定业务标识和限定时间窗查服务端异常；进程内模拟请求核对测试上下文应用日志，无法访问时标明未覆盖 |
| 问题处理 | 失败时区分预期、测试环境数据或配置、环境与代码；记录有界数据来源、配置变更或 fixer 修复及受影响步骤复测 |
| 发布后复验 | 记录目标测试环境、实际版本、全流程接口结果及返回、适用 SQL 和日志证据；未获发布授权时标记待发布与待复验 |
| 验证点 | 路由、参数绑定、签名、认证与鉴权、接口返回数据、适用的 SQL 数据及必要副作用的断言；直接调用或绕过校验须标明未覆盖环节 |
| 风险条件 | L4 填异常触发、并发量或数据规模；其他等级 N/A |
| 执行状态 | 默认 `NOT_RUN`；执行后 `PASSED`、`FAILED` 或 `BLOCKED` |

## 代表性接口连通验证

本次测试含适用 HTTP 接口且获运行授权时，首次选能经过正常签名或登录校验、路由及业务处理的接口执行；本轮首个适用接口可兼作检查，同轮且环境、服务版本、公共配置基线和前置数据状态一致时可复用其证据。非 HTTP 测试记 N/A；有接口但无运行授权记 `NOT_RUN`，获授权但必需条件缺失记 `BLOCKED`。单接口通过不代表完整流程通过，也不阻断与该接口无依赖的已授权测试。

| 接口与请求 | 环境、服务版本及公共配置基线 | 前置数据与业务键 | 返回、适用 SQL 与日志证据 | 状态及延期或失败原因 |
|------------|--------------------------------|--------------------|----------------------------|------------------------|
| 待选择 | 待核实 | 待核实 | 待执行 | `NOT_RUN` |

|------------------|------------------------|--------------------------|---------------------------|------------------|------------------------------|------------------|
| 发布前 / TC-001 / 待填写 | 待执行 | `NOT_RUN` | 待核实 | 待核实 | `NOT_RUN` | 待执行 |
| 发布后 / TC-001 / 待填写 | 待发布 | `NOT_RUN` | 待核实 | 待核实 | `NOT_RUN`（待复验） | 待执行 |

测试产物按需包含接口清单、用例、测试前数据表、逐轮结果表、请求与返回断言、适用 SQL 和日志证据索引、问题处理及清理记录；计划与实际分开，未要求落盘时在对话中交付。执行记录逐接口或流程附目标、环境、命令、返回断言、适用的 SQL 与日志证据及未覆盖项；无运行授权记 `NOT_RUN`，获授权但必需验证点没有执行证据时标记 `BLOCKED`，不得标记通过。测试环境数据和配置修改、代码修复及发布分别遵守项目规则与对应角色授权。
