# kset-framework UI/UX 规范

> project-init 生成。本文件是项目作用域的界面规范，不是独立规范。执行约束以 [项目规则](../rules/kset-framework-project-rules.md) 为准，技术事实以 [project-spec](../../docs/overview/design/project-spec.md) 与实际源码为准；文档状态与证据按 [项目文档规范](../standards/kset-framework-requirements-designer/references/project-documentation.md) 处理。

## 适用范围

涉及页面、组件、导航、表单、反馈、响应式或无障碍的设计、实现与评审时使用；无界面任务不适用。项目已有组件、设计 token 与交互约定须先核实，不能从技术依赖推断界面事实。

## 规范

R001: 先确定目标用户、主要任务、设备与输入方式，再核对现有页面、组件和设计资源；未证实的约定标为待核实。
R002: 先梳理入口、关键任务路径、成功结果及错误恢复，再确定信息层级、导航和视觉表达。
R003: 控件须有可理解的名称、键盘焦点和状态反馈；颜色不得是状态的唯一表达，表单错误须说明可采取的下一步并保留可恢复的输入。
R004: 高风险操作须有与风险相称的取消、确认或撤销路径；加载、空、失败、成功及极限状态按实际场景定义。
R005: Web 普通文本对比度至少 4.5:1，大文本及关键非文本控件至少 3:1；触控目标按目标平台要求核验，Web 按 WCAG 2.2 的 24 CSS px 及适用例外判断。
R006: 导航、焦点和返回路径须可预期；图表提供标签、单位与非颜色区分，媒体提供适用的替代文本，动效尊重减少动态效果偏好。
R007: 实施时复用项目现有框架、组件及设计 token；本规范不授权修改源码、接口契约或部署。
R008: 交付前按目标视口、长文本、缩放和输入方式核对关键路径；未实际运行或缺少目标用户验证时分别标记未验证或设计假设。

## 文档输出

用户要求保存界面规范时，关联需求或场景编号、关键页面状态与可定位的验收依据；沿用项目已有正式位置。正式界面文档按项目规则进入 `docs/{module}/design/ui/` 的适用分类，未定稿草稿进入 `tmp/drafts/ui/`，不为无界面任务建立空文档。
